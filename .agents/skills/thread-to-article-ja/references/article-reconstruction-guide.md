# 記事再構成ガイド

## 目的

素材化テンプレートの内容を、読み手が迷わない技術記事へ再配置する。  
結論だけを並べず、判断の根拠と思考遷移が追える本文にする。

## 再構成手順

1. `INPUT_METADATA` と `PROBLEM` から導入段落を作る。  
読者の悩みと記事の到達点を明示する。

2. `INSIGHTS` と `LOGIC` を本文の主軸にする。  
「何を」「なぜ」の順で配置し、主張を単なる感想にしない。

3. `STRUCTURE` と `DECISION_RULES` を見出し化する。  
判断に使えるルールとして書き換え、実務で再利用できる形にする。

4. `THINKING_FLOW` を短いストーリーにする。  
初期の迷い、途中の転換、最終結論の順で文脈を接続する。

5. `EXAMPLES` と `APPLICATION` で抽象と具体を往復させる。  
具体例を置いたうえで、他案件へ適用する視点を示す。

6. `HOOK` を導入や小見出しに反映する。  
読者が読み進める理由を最初に作る。

## 汎用記事構造への当て込み

記事のテーマに依存せず、次の骨組みを優先して組み立てる。

1. frontmatter  
`title` / `updated` / `category` を先頭に置く。

2. 前述（導入）  
執筆意図と読者課題を明示する。

3. 内容（本文）  
`STRUCTURE` のカテゴリを見出しへ展開する。  
各見出しで「対象」「判断」「整理」「運用」の順に論点を配置する。

4. 後述（結論）  
記事冒頭の課題に対して、何が解消されたかを再掲する。

必要なら次のひな形をそのまま使う。

```markdown
---
title: {{記事タイトル}}
updated: {{更新日}}
category: {{カテゴリ}}
---

<!-- 前述：執筆意図を明確にし、何を書いているのかが伝わるようにする -->

{{導入本文}}

<!-- 内容：考え方を書き連ねる -->

## {{論点1}}
- {{要点}}

## {{論点2}}
- {{要点}}

## {{論点3}}
- {{要点}}

## {{論点4}}
- {{要点}}

<!-- 後述：タイトルや前述との整合性を取る -->

## 最後に
{{結論本文}}
```

## 品質チェック

- 要約で終わらず、判断理由が明記されているか。
- 各見出しが独立して再利用できるか。
- 具体例が抽象論の裏付けになっているか。
- 非コードの文章が日本語で統一されているか。
