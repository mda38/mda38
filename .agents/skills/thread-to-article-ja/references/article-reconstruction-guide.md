# 記事再構成ガイド

## 目的

素材化テンプレートの内容を、読み手が迷わない技術記事へ再配置する。  
結論だけを並べず、判断の根拠と思考遷移が追える本文にする。

## 再構成手順

1. `INPUT_METADATA` と `PROBLEM` から導入段落を作る。  
読者の悩みと記事の到達点を明示する。

2. `INSIGHTS` と `LOGIC` を本文の主軸にする。  
「何を」「なぜ」の順で配置し、主張を単なる感想にしない。

3. `STRUCTURE` と `DECISION_RULES` を見出し化する。  
判断に使えるルールとして書き換え、実務で再利用できる形にする。

4. `THINKING_FLOW` を短いストーリーにする。  
初期の迷い、途中の転換、最終結論の順で文脈を接続する。

5. `EXAMPLES` と `APPLICATION` で抽象と具体を往復させる。  
具体例を置いたうえで、他案件へ適用する視点を示す。

6. `HOOK` を導入や小見出しに反映する。  
読者が読み進める理由を最初に作る。

## フロントエンドテスト記事への当て込み

次の骨子を優先して組み立てる。

- テスト対象を把握
- テスト価値を判断
- テスト分類を整理
- テストコードの実行タイミング

導入では「手法より考え方が重要」という主張を置き、  
結びでは「もやもやが解消された理由」を再掲する。

## 品質チェック

- 要約で終わらず、判断理由が明記されているか。
- 各見出しが独立して再利用できるか。
- 具体例が抽象論の裏付けになっているか。
- 非コードの文章が日本語で統一されているか。
